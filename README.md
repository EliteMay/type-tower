3人で制作する「TYPE TOWER」の制作方針、学校日程、作る順番、共同作業方法、STEPごとの追加コードをまとめるサイトです。

## Source of Truth

ゲーム本体の実装は `EliteMay/type-tower-a` の `main` を正とします。

- 関数名
- 変数名
- HTML構造
- 現在の実装状態
- データファイルの有無

が方針サイトと食い違った場合は、原則として**方針サイト側をゲーム本体へ合わせて修正**します。

## STEP追加コードの重要ルール

STEPを進めるたびにファイル全文を貼り直しません。

1. **ゲーム本体 `EliteMay/type-tower-a` の現在コードを正とする**
2. **既存コードをそのまま残す**
3. 新しいCSSルールやJavaScript関数は、原則としてファイル末尾へ追加
4. HTMLや既存関数の途中へ入れる場合は、追加場所を具体的に示す
5. 既存処理の変更が必要な場合だけ、対象ブロックを部分置換する
6. 前STEPの実装を消さない
7. JSONへの問題追加は配列の最後の `]` より前へ追加する

### 追加場所の書き方

位置案内は必ず次の3点をセットにします。

- 対象ファイル
- 大体の行番号
- 本体に実在するコードを目印にした「直後 / 直前」

例:

```text
js/game.js の約37行目。
`resetQuestionPool();` の直後、`startGameTimer();` の直前に追加。
```

前のSTEPを追加すると行番号はずれるため、**ずれた場合は行番号より目印コードを優先**します。

## 今回作らない機能

次の機能は要件から外します。

- COMBO
- 難易度
- 記録保存

そのため:

- STEP 6は **TIME（制限時間）のみ**
- STEP 8は **RESULT詳細のみ**
- `localStorage` 等を使ったゲーム記録保存は作らない

制作方針サイトの進捗チェック保存は、ゲーム本体の記録保存とは別物なのでそのまま使います。

## TIMEのルール

STEP 6のTIMEは、**問題ごとの制限時間ではなくゲーム全体の制限時間**です。

現在の設定:

- ゲーム開始時: **90秒**
- 問題が変わっても残り時間はリセットしない
- 10Fクリアまで同じタイマーを使う
- 0秒になったら `TIME UP` としてRESULTへ進む
- 再挑戦時は90秒からやり直す

秒数を後から変更する場合は、ゲーム側の `GAME_TIME` 定数だけを変更できる形にします。

## 現在のゲーム本体

2026-09-09確認時点では、**HOMEとSTEP 9の階移動演出・二重入力防止までコード反映済み / 実ブラウザでの最終確認待ち**です。

### 現在の入口: HOME

今のゲーム本体は `home` から始まります。

- `assets/videos/menu-bg.mp4` をHOME背景として自動再生・無限ループ
- 大きな `TYPE TOWER` タイトルを表示
- 大きなSTARTボタンを表示
- STARTを押すとSELECTへ進む
- **HOME内にはロゴ画像を表示しない**
- 用意済みロゴは、画像ファイルが本体へ追加されたらブラウザのタブ用faviconとして使う

### SELECT

- `assets/videos/menu-bg.mp4` を背景動画として自動再生・無限ループ
- 漢字 / 英訳 / 和訳の3つの選択肢を横並び
- ボタンを押すと `main.js` が `selectedMode` を保持してGAMEへ切り替える
- 選択モードは `[data-screen="game"]` の `data-mode` にも反映する

### GAME / RESULT

- `remainingQuestions` を使い、問題プールを使い切るまで同じ問題の重複を避ける
- 入力欄へ答えを入れてEnterすると、正解 / MISSを判定できる
- `isJudging` で判定処理中の二重送信を防ぐ
- 正解で +1F
- MISSで -1F
- 1F未満には下がらない
- 1F〜10Fの階数表示あり
- ゲーム全体90秒のTIMEあり
- 9Fで正解すると10Fへ進み、**10Fの問題を正解したらCLEARしてRESULTへ進む**
- TIMEが0秒になった場合もRESULTへ進む
- RESULTに正解数 / MISS数 / 正答率 / プレイ時間を表示する処理あり
- 再挑戦ボタンあり
- RESULTから塔選択へ戻るボタンあり
- GAME画面全体の背景は `assets/images/sky-bg.jpg`
- ゲームステージ背景は選択した塔で切り替える
  - `kanji` → `tower-blue.jpg`
  - `eiyaku` → `tower-light.jpg`
  - `wayaku` → `tower-dark.jpg`
- `js/effects.js` に正解 / MISSのフラッシュと階移動演出あり
- 正解時は上方向、MISS時は下方向だけ演出する
- `js/storage.js` は空で、今回のゲーム要件では使用しない

### データ

3つのJSONを `selectedMode` に応じて切り替えて読み込みます。

- `kanji` → `data/kanji.json`
- `eiyaku` → `data/ja-en.json`
- `wayaku` → `data/en-ja.json`

`game.js` の `DATA_FILES` と `loadQuestions()` は3モード対応済みです。

## HOMEとロゴの方針

HOMEの必須要素:

- **でっかい `TYPE TOWER` タイトル**
- **でっかいSTARTボタン**
- 背景
- STARTを押すとSELECTへ進む

ロゴはHOMEには表示しません。

- 用意済みロゴは **ブラウザのタブ用favicon** として使う
- 2026-09-09時点の `type-tower-a` ではロゴ画像ファイルを確認できていないため、画像が本体へ追加された時点で `<link rel="icon">` を設定する

### 完成時の主要Flow

```text
HOME
→ 大きなタイトル
→ 大きなSTART
→ SELECT
→ 塔を選ぶ
→ 選択モードの問題を読み込む
→ GAME
→ 正解 / MISS
→ 階数変化
→ 10F CLEAR または TIME UP
→ RESULT
→ SELECT
```

RESULT後は今までどおりSELECTへ戻る形を基本とします。

## 制作順

1. 3画面の箱 + SELECTの3つの塔 — 実装済み
2. 漢字問題を表示 — 実装済み
3. タイピング判定 — 実装済み
4. 正解 +1F / MISS -1F / **10Fの問題を正解してCLEAR** — 実装済み
5. RESULT・再挑戦・SELECTへ戻る — **本体反映済み**
6. ゲーム全体TIME 90秒 — **本体反映済み**
7. 英訳・和訳の塔を接続 — **本体反映済み / 動作確認待ち**
8. RESULT詳細（正答率・プレイ時間） — **本体反映済み / 動作確認待ち**
9. 階移動演出・二重入力防止 — **本体反映済み / 動作確認待ち**
10. 問題追加・最終テスト・動画準備

HOME（大タイトル・大START）は本体へ反映済みです。ロゴはHOMEではなくfaviconとして使います。

## 3人開発の基本方針

基本は3人で一緒に作ります。

ゲームの中心部分は完全分業せず、3人で目的を確認し、1人がその時間の操作役になります。操作役は機能や時間ごとに交代します。

分担しやすいもの:

- 問題追加
- 問題調査
- ロゴ・背景・塔・敵などの素材準備
- テスト
- 動画素材

GitHubでは人別ではなく、タイピング、問題追加、RESULTなど作業内容ごとにBranchを分けます。同じファイルを別々に同時編集しないことを優先します。

## 進捗保存

制作方針ページのSTEPチェックはブラウザ内に保存します。現在の実装で完了しているSTEP 1〜4は基準状態として扱います。

STEP 5〜9は本体へコード反映済みですが、必要な実ブラウザ確認が終わるまでは自動完了扱いにしません。

これは**制作方針サイト自身のチェック状態保存**であり、ゲーム本体のプレイ記録保存機能ではありません。
