# TYPE TOWER 制作ロードマップ

3人で制作する「TYPE TOWER」の開発順、学校日程、GitHub初心者向けの共同開発手順をまとめたサイトです。

## 最初に読むページ

GitHubを初めて使うメンバーは、制作を始める前に `github-guide.html` を読んでください。

このページでは、GitHubとは何か、Repository / Branch / Commit / Pull Request / Merge、Collaborator追加、GitHub上の直接編集、github.dev、Commit & Push、Conflict時の基本対応まで説明しています。

## 3人開発の基本方針

**基本は3人で一緒に作ります。**

難しい部分やゲームの中心部分は完全分業せず、1人をその時間の操作役にしてgithub.devでコードを書き、残り2人がコード・画面・次の処理を確認します。操作役は機能や時間ごとに交代します。

分担するのは、問題JSON追加、問題調査、ロゴ案、素材探し、テスト、動画素材など、他の作業とぶつかりにくい独立作業を中心にします。

Branchは人別ではなく作業別にします。

`feature/typing` / `feature/questions` / `feature/result`

通常の流れは次です。

`NEXT確認 → 操作役を決める → 3人で実装 → 必要なら単純作業だけ分担 → Commit → Pull Request → Merge → 3人でmainを確認`

## HOME画面の確定方針

TYPE TOWERを開いた最初の画面は、別のSTART画面やSELECT画面を挟みません。

**画面いっぱいの空を背景に固定し、その上へ3つの塔を並べます。各塔の真下に開始ボタンを置き、ボタンを押すと対応するゲームがそのまま始まります。**

3つの塔は次の3モードに対応します。

- 漢字の塔：漢字 → 読み
- 英訳の塔：日本語 → 英語
- 和訳の塔：英語 → 日本語

HOMEでモードを選ぶため、独立した `SELECT` 画面は作りません。

基本画面は次の3つです。

`HOME → GAME → RESULT`

### HOMEからゲーム開始まで

1. サイトを開く
2. 空背景と3つの塔が最初から表示される
3. 挑戦する塔の下にあるボタンを押す
4. `selectedMode` にその塔のモードを保存する
5. `floor = 1`、COMBOやスコアを初期化する
6. HOMEを隠してGAMEを表示する
7. 選択したモードの問題データを読み込み、1問目を表示する

最初の実装ではHOMEに3つの塔を表示しますが、**漢字の塔だけゲーム開始できればOK**です。残り2つの塔はゲームループ完成後に同じ仕組みへ接続します。

## 背景と階移動の方針

空背景はHOME / GAMEの一番後ろで基本的に固定します。

正解・MISSで階を移動するときは、画面全体や空を動画として流すのではなく、**塔内部の背景レイヤーだけを画像 + CSSアニメーションで上下へスライド**させます。

- 正解：次の階が上から入ってくる
- MISS：下の階へ戻る方向にスライドする
- 空：大きく動かさない
- 問題カード / 入力欄 / TIME / COMBO：HUDとして基本固定
- 敵：塔内部側のレイヤーで、問題文を隠さない

通常の1階移動には動画を使わず、必要ならCLEARやボス登場など特別演出だけ短い動画を検討します。

## 学校日程

- **9/1**: 企画・開発方針・GitHub準備
- **9/2〜9/4**: ゲームの核。漢字の塔でHOMEからRESULTまで遊べる状態を目指す
- **9/8〜9/9**: タイマー、コンボ、難易度、残り2つの塔、RESULT
- **9/10〜9/11**: HOMEの空・3塔、GAME画面、階移動、ロゴ、問題追加、仕上げ
- **9/15**: 最終通しテスト、重大バグ修正、動画構成・撮影準備
- **9/16〜9/17**: 動画制作・発表準備。原則として新しいゲーム機能は追加しない

遅れた場合は新機能を増やすのではなく、「最後まで安定して遊べること」を優先します。

## 一番重要な制作方針

最初から3モード・演出・ランキングなどを同時に作りません。

まず **漢字の塔1つだけ**で、次の流れを完成させます。

`HOMEの漢字の塔ボタン → 問題表示 → 入力 → 正解/MISS判定 → 階数変化 → 10FでCLEAR → RESULT → HOME`

このゲームループが最後まで動いてから、タイマー・コンボ・難易度・残り2つの塔・見た目を追加します。

## 制作順

1. 3画面の箱 + HOMEの3つの塔を作る
2. 漢字問題を表示する
3. タイピング判定を完成させる
4. タワーの上下とクリアをつなぐ
5. 漢字の塔を最初から最後まで遊べる状態にする
6. タイマー・コンボ・難易度を追加する
7. 残り2つの塔をゲームにつなぐ
8. RESULT・記録保存を完成させる
9. HOME / GAMEの見た目と階移動を仕上げる
10. 問題追加・テスト・動画準備

各STEPにはサイト上で「作るもの」「完了条件」「3人でやるか / 分担できるか」を表示します。

さらに各STEPの **「作り方と記入例を見る」** を押すと小窓が開き、使うHTML / CSS / JavaScript / JSON、触るファイル、実装順、記入例を確認できます。

## GAME画面のビジュアル方針

HOMEとGAMEの世界観をつなげます。

### HOME

- 背景：画面いっぱいの明るい空
- 中央：3つの塔
- 各塔の下：塔名、モード説明、開始ボタン
- 3つの塔：漢字 / 英訳 / 和訳

### GAME

- 最背面：HOMEと同じ空
- 中央：塔を横から切ったように見える石造りの内部
- 左：1F〜10Fの縦型フロア表示
- 中央上：現在階
- 右上：TIME
- 中央：問題カード
- 問題カードの後ろ：敵
- 中央下：大きい入力欄
- 入力欄の下：COMBO、MISS -1F / 正解 +1F

色は **青空 / 薄いベージュの石材 / 濃紺 / 金** を基本にし、敵は濃い紫〜黒、目だけ赤〜橙を想定します。

敵や背景より、問題文と入力欄の読みやすさを優先します。

## 制作ルール

- 前のSTEPが動いてから次へ進む
- STEP 5までは追加機能よりゲームループ完成を優先
- HOMEは固定の空 + 3つの塔 + 各塔の開始ボタン
- 独立したSELECT画面は作らない
- 最初は漢字の塔だけ動けばよい
- 基本は3人で一緒に実装する
- 分担は独立した単純作業を中心にする
- 同じファイルを別々に同時編集しない
- Branchは人別ではなく作業別にする
- Pull Requestで変更を確認してからmainへMergeする
- 各STEP終了時に3人でmainをブラウザ確認する
- 9/15の最終テスト後は新しいゲーム機能を増やさない
- 背景や敵より問題と入力欄の読みやすさを優先する
