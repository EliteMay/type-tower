# TYPE TOWER 制作ロードマップ

3人・約2週間で制作する「TYPE TOWER」の開発順と、GitHub初心者向けの共同開発手順をまとめたサイトです。

## 最初に読むページ

GitHubを初めて使うメンバーは、制作を始める前に `github-guide.html` を読んでください。

このページでは次を説明しています。

- GitHubとは何か
- Repository / main / Branch / Commit / Pull Request / Merge
- Collaboratorの追加
- Branchの作り方
- GitHub上で直接ファイルを編集する方法
- github.devを使ってVS Codeのように編集する方法
- Commit & Push
- Pull RequestとMerge
- 3人で同時に作業するときのルール
- Conflictなどで困ったときの基本対応

## 3人開発の基本ルール

`main` は完成版の基準として扱います。

通常の作業は、次の順番です。

`main → 作業用Branch → コードを書く → Commit → Pull Request → 確認 → Merge → mainで動作確認`

小さい1ファイル修正はGitHubのファイルエディター、HTML/CSS/JavaScriptなど複数ファイルを触る通常作業は `github.dev` を使います。

## 一番重要な制作方針

最初から3モード・演出・ランキングなどを同時に作りません。

まず **漢字モード1つだけ**で、次の流れを完成させます。

`問題表示 → 入力 → 正解/MISS判定 → 階数変化 → 10FでCLEAR → RESULT`

このゲームループが最後まで動いてから、タイマー・コンボ・難易度・残り2モード・見た目を追加します。

## 制作順

1. 4画面の箱を作る
2. 漢字問題を表示する
3. タイピング判定を完成させる
4. タワーの上下とクリアをつなぐ
5. 最初から最後まで遊べる状態にする
6. タイマー・コンボ・難易度を追加する
7. 残り2モードを追加する
8. RESULT・記録保存を完成させる
9. 画像案を基準にGAME画面の見た目と演出を仕上げる
10. 問題追加・テスト・発表準備

各STEPにはサイト上で「作るもの」「完了条件」を表示します。

さらに各STEPの **「実装のしかたを見る」** を押すと小窓が開き、次を確認できます。

- その機能で使うHTML / CSS / JavaScript / JSONなど
- 主に触るファイル
- 実際に作る順番
- 最小のコード例
- 初心者が詰まりやすい注意点

STEP 9だけは **「画像案からの作り方を見る」** になっており、今回決めたGAME画面の完成イメージをどの順番で組むかも確認できます。

詳細は常時表示せず、必要なSTEPだけ小窓で確認する構成です。

## GAME画面のビジュアル方針

今回作成したカラー案を、GAME画面の方向性として使います。画像をそのまま貼って完成させるのではなく、構造をHTML/CSSで再現し、必要な背景・敵・装飾だけ画像素材として追加します。

主な構成は次の通りです。

- 中央：塔を横から切ったように見える石造りの内部
- 左右：塔の外側に明るい青空と雲が見える
- 左：1F〜10Fの縦型フロア表示。現在階を濃紺+金などで強調
- 中央上：現在階を大きく表示
- 右上：TIME
- 中央：問題カード
- 問題カードの後ろ：敵。頭・目・腕などがカード外から見える程度
- 中央下：大きい入力欄
- 入力欄の下：COMBO、MISS -1F / 正解 +1F

色は **青空 / 薄いベージュの石材 / 濃紺 / 金** を基本とし、敵は濃い紫〜黒、目だけ赤〜橙のアクセントを想定します。

敵や背景が目立ちすぎて問題文を読みにくくしないことを最優先にします。

### 見た目を作る順番

`配置だけ決める → 塔の断面背景 → 左右の空 → 敵レイヤー → HUD → 色 → 正解/MISS/階移動演出 → レスポンシブ確認`

機能完成前にこの見た目へ作り込まず、STEP 9でまとめて仕上げます。ただし左の階数、TIME、COMBOなど、機能として必要な表示はそれぞれのSTEPで先に動く状態にします。

## ゲーム本体の置き場所

制作ガイドとゲーム本体を混ぜないため、ゲームは `game/` フォルダに作る方針です。

```text
game/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  ├─ main.js
│  ├─ game.js
│  ├─ storage.js
│  └─ effects.js
├─ data/
│  ├─ kanji.json
│  ├─ ja-en.json
│  └─ en-ja.json
└─ assets/
   ├─ images/
   │  ├─ tower/
   │  └─ enemies/
   └─ sounds/
```

最初から全ファイルを作る必要はありません。ロードマップのSTEPに合わせて必要になったファイルだけ追加します。

## 制作ルール

- 前のSTEPが動いてから次へ進む
- STEP 5までは追加機能よりゲームループ完成を優先
- 新しい案が出ても、そのSTEPに必要なければ後回し
- 14日目は新機能を追加しない
- 作業用Branchを作ってから編集する
- 同じファイルを複数人が触る場合は先に共有する
- Pull Requestで変更を確認してからmainへMergeする
- 各STEP終了時にmainをブラウザで確認する
- 背景や敵より、問題と入力欄の読みやすさを優先する

## ファイル

- `index.html` : 制作ロードマップ本体
- `styles.css` : 制作ロードマップのデザイン
- `app.js` : STEP進捗保存・次の作業表示・実装詳細の小窓
- `roadmap-details.css` : 実装詳細小窓のデザイン
- `github-guide.html` : GitHub初心者向け共同開発ガイド
- `github-guide.css` : GitHubガイドのデザイン

## 保存

進捗チェックは `localStorage` に保存します。保存に失敗してもロードマップ自体は利用できます。
