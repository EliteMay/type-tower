# TYPE TOWER 制作ロードマップ

3人で制作する「TYPE TOWER」の開発順、学校日程、GitHub初心者向けの共同開発手順をまとめたサイトです。

## 最初に読むページ

GitHubを初めて使うメンバーは、制作を始める前に `github-guide.html` を読んでください。

このページでは、GitHubとは何か、Repository / Branch / Commit / Pull Request / Merge、Collaborator追加、GitHub上の直接編集、github.dev、Commit & Push、Conflict時の基本対応まで説明しています。

## 3人開発の基本方針

**基本は3人で一緒に作ります。**

難しい部分やゲームの中心部分は完全分業せず、1人をその時間の操作役にしてgithub.devでコードを書き、残り2人がコード・画面・次の処理を確認します。操作役は機能や時間ごとに交代します。

分担するのは、問題JSON追加、問題調査、ロゴ案、素材探し、テスト、動画素材など、他の作業とぶつかりにくい独立作業を中心にします。

Branchは人別ではなく作業別にします。

`feature/typing` / `feature/questions` / `feature/result`

通常の流れは次です。

`NEXT確認 → 操作役を決める → 3人で実装 → 必要なら単純作業だけ分担 → Commit → Pull Request → Merge → 3人でmainを確認`

## 学校日程

- **9/1**: 企画・開発方針・GitHub準備
- **9/2〜9/4**: ゲームの核。漢字1モードでHOMEからRESULTまで遊べる状態を目指す
- **9/8〜9/9**: タイマー、コンボ、難易度、残り2モード、RESULT
- **9/10〜9/11**: GAME画面の見た目、ロゴ、問題追加、仕上げ
- **9/15**: 最終通しテスト、重大バグ修正、動画構成・撮影準備
- **9/16〜9/17**: 動画制作・発表準備。原則として新しいゲーム機能は追加しない

遅れた場合は新機能を増やすのではなく、「最後まで安定して遊べること」を優先します。

## 一番重要な制作方針

最初から3モード・演出・ランキングなどを同時に作りません。

まず **漢字モード1つだけ**で、次の流れを完成させます。

`問題表示 → 入力 → 正解/MISS判定 → 階数変化 → 10FでCLEAR → RESULT`

このゲームループが最後まで動いてから、タイマー・コンボ・難易度・残り2モード・見た目を追加します。

## 制作順

1. 4画面の箱を作る
2. 漢字問題を表示する
3. タイピング判定を完成させる
4. タワーの上下とクリアをつなぐ
5. 最初から最後まで遊べる状態にする
6. タイマー・コンボ・難易度を追加する
7. 残り2モードを追加する
8. RESULT・記録保存を完成させる
9. 参考画像を基準にGAME画面の見た目と演出を仕上げる
10. 問題追加・テスト・動画準備

各STEPにはサイト上で「作るもの」「完了条件」「3人でやるか / 分担できるか」を表示します。

さらに各STEPの **「実装のしかたを見る」** を押すと小窓が開き、使うHTML / CSS / JavaScript / JSON、触るファイル、実装順、最小コード例を確認できます。

## GAME画面のビジュアル方針

カラー参考案をGAME画面の方向性として使います。画像をそのまま完成画面として貼るのではなく、構造をHTML/CSSで再現し、必要な背景・敵・装飾だけ画像素材として追加します。

- 中央：塔を横から切ったように見える石造りの内部
- 左右：明るい青空と雲
- 左：1F〜10Fの縦型フロア表示
- 中央上：現在階
- 右上：TIME
- 中央：問題カード
- 問題カードの後ろ：敵
- 中央下：大きい入力欄
- 入力欄の下：COMBO、MISS -1F / 正解 +1F

色は **青空 / 薄いベージュの石材 / 濃紺 / 金** を基本にし、敵は濃い紫〜黒、目だけ赤〜橙を想定します。

敵や背景より、問題文と入力欄の読みやすさを優先します。

## 制作ルール

- 前のSTEPが動いてから次へ進む
- STEP 5までは追加機能よりゲームループ完成を優先
- 基本は3人で一緒に実装する
- 分担は独立した単純作業を中心にする
- 同じファイルを別々に同時編集しない
- Branchは人別ではなく作業別にする
- Pull Requestで変更を確認してからmainへMergeする
- 各STEP終了時に3人でmainをブラウザ確認する
- 9/15の最終テスト後は新しいゲーム機能を増やさない
- 背景や敵より問題と入力欄の読みやすさを優先する

## 主なファイル

- `index.html` : 制作ロードマップ本体
- `styles.css` : 制作ロードマップのデザイン
- `app.js` : STEP進捗保存・次の作業表示・実装詳細の小窓
- `roadmap-details.css` : 実装詳細小窓とGAME参考画面の表示
- `assets/type-tower-game-reference.svg` : GAME画面の参考イメージ
- `github-guide.html` : GitHub初心者向け共同開発ガイド
- `github-guide.css` : GitHubガイドのデザイン

## 保存

進捗チェックは `localStorage` に保存します。保存に失敗してもロードマップ自体は利用できます。
