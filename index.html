01 / BACKGROUND

空はずっと固定

HOMEでもGAMEでも、画面いっぱいの空を一番後ろに固定します。階を上がる演出でも空自体は大きく動かさず、塔側だけを動かします。

02 / TOWERS

最初から3つの塔を横並び

3モードを3つの塔として見せます。別のSELECT画面は作らず、どの塔に入るかをHOME画面で選びます。

03 / BUTTON

各塔の真下に開始ボタン

塔そのものをクリック必須にはせず、分かりやすいボタンを各塔の下へ置きます。押した塔のモードを保存して、そのままGAMEへ移動します。

04 / GAME START

押したら1Fから即ゲーム開始

ボタン → selectedModeを設定 → HOMEを隠す → GAME表示 → floorを1へ初期化 → 最初の問題を表示、までを1つの開始処理にまとめます。

STEP Aサイトを開く

空背景 + 3つの塔が最初から表示される。

STEP B塔を選ぶ

漢字 / 英訳 / 和訳のどれかのボタンを押す。

STEP Cモードを保存

selectedModeへ選択したモードを入れる。

STEP Dゲーム開始

1F・0COMBO・最初の問題から開始する。

JavaScriptの流れ

document.querySelectorAll('[data-mode]')
  .forEach(button => {
    button.addEventListener('click', () => {
      startGame(button.dataset.mode);
    });
  });

function startGame(mode) {
  selectedMode = mode;
  floor = 1;
  showScreen('game');
  loadModeQuestions();
}
階を上がるとき： 空背景は固定したまま、塔内部の背景・敵・階層だけを上方向へスライドさせます。通常の1F移動に動画は使わず、画像レイヤー + CSSアニメーションで動かす方針にします。問題カード・入力欄・TIMEなどのHUDは基本固定です。

HOW WE BUILD

基本は3人で一緒に作る

担当を完全に分けません。難しい部分・ゲームの中心部分は3人で考え、1人が操作役としてコードを書き、残り2人が確認・相談します。

基本

ゲームの中心は3人で作る

画面切替、タイピング判定、階数、タイマー、ゲームループ、バグ修正などは一緒に進める。

操作役

コードを書く人は交代

その時間は1人だけがgithub.devを操作。機能や時間ごとに操作役を交代し、全員がGitHubとコードを触る。

分担OK

独立した単純作業だけ並行

問題JSON追加、問題調査、ロゴ案、素材探し、テスト、動画素材など、同じコードを同時に触らない作業を分担する。

Branchの考え方

person-a のような人別ではなく、feature/typing・feature/questions・feature/result のように作業単位で作る。
